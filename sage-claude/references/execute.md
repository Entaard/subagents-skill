# Execute and watch

Your job here: launch the wave, keep the ledger current while it runs, pick the rung a failure earns rather than the one an attempt count suggests, and read the two figures nothing prints for you — spend and parent occupancy.

- Launch independent units as **one parallel batch up to the cap**. Background by default; synchronous only when the result blocks your next step.
- **Dispatch the model the plan named.** Deciding mid-run that a unit needs more judgment is often correct; changing its model without a record is not. State the change and the reason in `### Decisions and deviations` before dispatching. Tier escalation on the failure ladder is already part of the plan: log it, do not re-derive it.
- While agents run, do non-overlapping read-only work. **Never fabricate or predict a pending agent's result.** Do not poll a harness that notifies.
- Any writer in a shared tree → run the snapshot protocol (`dispatch.md`, `## Snapshot protocol`). **`/rewind` will not undo what a subagent wrote** (`harness.md`, `## Cautions`), so that baseline is the only way back — take it before the writer starts, not after something looks wrong. **The protocol covers your own tree too**: the logged run that destroyed a working copy was the parent's doing, not a writer's. Snapshot before editing inline, commit explicit paths while any agent is running, and never edit a tree a measuring agent is reading. Every mutation-probing unit, reviewers included, gets worktree isolation, and an installer-execution verifier gets a sandbox `HOME` for the same reason a writer gets a worktree: it has to mutate a real tree to learn anything. Prove the worktree recipe (`ln -s node_modules`, `rev-parse HEAD`) with one command before launching on it, and prune changed worktrees after each wave — auto-clean removes only unchanged ones (calibration: established).
- **A parent-kept row that writes or changes code loads `clean-code` before your first edit on it**, and its `evidence` cell records the load; `decompose.md` owns why, and one load covers every inline edit that follows.
- **The failure ladder, per unit — diagnose the signature, then pick the rung it earns.** **Count signatures, not attempts**, and read the signature — same file, symbol, error class — from the *first* failure, because the causes want opposite actions. A **specification** signature (wrong scope, a file missed, a different question answered) says the brief was wrong: dispatch a **fresh agent at the same tier**, brief corrected and the last attempt's failure named in it. Never steer here — a steer keeps the context that misread the brief, and the ~4–7× discount does not transfer: it was measured on a *successful* verifier asked one more narrow question, never on an agent whose own context is the defect. A **capability** signature (right approach, could not finish, looping) says the agent is the bottleneck: steer the same agent with a sharpened brief, then dispatch one tier up framed as full owner (above frontier, apex). A **different** signature on the second failure means the first rung worked and exposed a new cause: spend the rung *that* cause earns rather than charging the attempt — which is why specification-then-capability legitimately runs to three or four delegated attempts, and why `../SKILL.md`'s `## Defaults` carries no attempt count. **Two failures sharing one signature**, either cause: the loop is stuck rather than slow — take it inline **and reopen the plan**, the assumptions, the reproduction or the "done when" (`../SKILL.md`, `## Stop rule`, owns that clause). Scope-`blocked` is on no rung at all — a higher tier grants no extra tool, so fix the brief or re-route, and charge nothing. **Inline is a different actor, not a last resort**: the parent holds the run's whole context, can run a command and read the result before choosing the next one, and can change a plan no unit is allowed to change — so it clears a specification failure a same-tier retry would not, and hits the same wall on a genuine capability one. Log every abandoned disagreement in `### Decisions and deviations`; silent discard is forbidden, and it is a surfaced event at Step 6.
- **Run the ledger lint at every point that brings the ledger current, and once more at Step 6.** `~/.claude/skills/sage/bin/sage-lint.sh <ledger-path>` — a sibling of the watchdog probe. **Its run block is what you read** (`sed -n '1,/^# END RUN BLOCK/p'` on the installed file): the check list, the output line shape, the exit codes, and the degradation rule. The rest of its header is the maintainer's manual. It reads the ledger you just brought current and prints one line per record-integrity violation, nothing at all on a clean one. Fix what it names before launching the next wave. It fails *quiet* by design, so a check it cannot make is silence rather than a spurious line. **Read its stderr**: silence on stdout *with* a line on stderr names a missing core tool, which is a one-line fix — fix it and run again. Never disable the lint, not for that and not to quiet a violation. **A violation it still reports at Step 6 is a surfaced event.**

  It exists because asking was already tried: the *safety* prose was obeyed and the *bookkeeping* prose was dead — ledgers backfilled post-hoc with no live state word, one inventing a state the enum does not carry; blockers with no triage row; dispatches never entered in the unit table. The lint reads legality, never liveness: a backfilled ledger and a live one read identically to it, and a missing state column shadows the illegal-word check on the same file. A clean lint is not evidence you kept the rest.

- **Bring the ledger current before launching a wave and after each integration.** Every such point is four acts at once: a lint run; a `--status` read, which is where mid-flight spend and liveness come from since no per-unit rung fires on its own, and which now also carries each unit's `model=` and `compact=`. **`model=` is the measured value**: copy it into the Unit table's `model used` cell with the word `measured` at this point. A unit whose measured family or tier differs from its Plan row is a `### Decisions and deviations` row, written when you read it, because a swap happened that the run did not order. The parent's own `model=` is recorded, never judged, because the user may choose it per session; an occupancy check against the checkpoint rung; and a restamp of the ledger header line and `### Resume state` (`dispatch.md`, `## The ledger`). After a compaction, re-read the ledger before dispatching anything new (`../SKILL.md`, `## Compaction and resume`) — it is the only surviving record of the estimate the budget rail measures against, the write lease and snapshot baseline that are the only way back from a bad writer, and the signature count the failure ladder reads. **A unit whose `--status` line shows `compact=` above zero reported from a summary of its own work**: write a `### Decisions and deviations` row and surface it at Step 6.

**The watchdog.** Start it when the first wave launches, in three steps. The probe is `~/.claude/skills/sage/bin/sage-watch.sh`, and **its run block is what you read** (`sed -n '1,/^# END RUN BLOCK/p'` on that file) — the invocations, the env vars, the one rung, the line shapes. The rest of its header is the maintainer's manual; nothing below restates either.

1. **Resolve the directory before you probe, and never guess it.** Read the `output_file` path any dispatch returned, then **`readlink` it: the returned path is a symlink whose own parent is `tasks/`, never `subagents/`.** `readlink -f` lands on `<project>/<session-id>/subagents/agent-<id>.jsonl`, and that file's parent is the directory to probe. Take the session uuid from the **resolved target**, never from the returned path — the uuid one level above `tasks/` is unreliable rather than wrong, matching the target session about half the time, with both cases occurring inside a single `tasks/` directory. The layout is `<project>/<session-id>/subagents`, **one level deeper than `<project>/subagents`** — handed the shallow path, or an un-`readlink`ed `tasks/` path, the probe names the wrong path on stderr rather than exiting silently, so read step 2's **stderr** test and never the empty stdout alone: a directory that resolves but holds no readable `agent-*.jsonl` is a wrong path to fix, never a layout to give up on. **Then settle the session id, because a directory that resolves can still be the previous run's.** `--status` prints the uuid in every line; confirm it is this run's by grepping this run's own dispatch descriptions across `~/.claude/projects/*.jsonl`. One probe that skipped this reported `occupancy=296k pct=29%` during a run actually at 11%, and acting on it would have fired the checkpoint in a run's first minutes.
2. **Probe once**, before hosting anything — the installed path is not on `PATH`, so write it out, passing that **explicit** dir (never `-`) and the window Step 2 resolved: `SAGE_WINDOW=<window> SAGE_COMPACT_AT=<n> ~/.claude/skills/sage/bin/sage-watch.sh --status <subagents-dir>` — `SAGE_COMPACT_AT` only where the user stated a compaction point. Lines back, carrying this run's session id → the layout resolves. Nothing back **and nothing on stderr** → it cannot run here; disable it, write one ledger line, and never warn again. Nothing back **with a diagnostic on stderr** is neither: it names a dependency or a path, never a layout the probe cannot run on. `install.sh` reports the same dependency list once, up front, which is where that belongs — and for `jq` it deliberately continues rather than aborting, because the features that use it fail open, so a probe naming `jq` is that known degradation surfacing at the one moment it costs something rather than a new fault. An unresolvable path is a one-line fix. Fix what it names and probe again rather than disabling the sensor for the run. Carry `SAGE_WINDOW` always, not only when it differs from the default — an unset window is how the small-window defect reproduces.
3. **Host it** on `Monitor`, `persistent: true`, command `while true; do SAGE_WINDOW=<window> SAGE_COMPACT_AT=<n> ~/.claude/skills/sage/bin/sage-watch.sh <subagents-dir>; sleep 60; done` — the same explicit dir and the same env prefix, always. The script takes one sample and exits, so the loop is what makes it a watch, and 60s is the cadence its cost was measured at (`harness.md`). Every stdout line becomes a notification, so **silence is its default output** and it speaks only on the rung below.

| Trigger | Action | Seen by |
| --- | --- | --- |
| Parent occupancy crosses the checkpoint rung (`compact-at` minus `max(5% of the compaction point, 30k)`; it fires once per compaction segment, latched by a marker file under `SAGE_STATE_DIR`) | Checkpoint: bring the ledger current, restamp `### Resume state` with `checkpoint: turn <n>`, write one `### Decisions and deviations` row with room remaining, work remaining and reserve, and surface it. Never a handover. | watchdog + you |

The probe reads the parent transcript itself, but only when the subagents dir was passed explicitly — discovery can resolve a different session's directory, so the checkpoint must never fire on it (`../bin/sage-watch.sh` header, DISCOVERY RULE).

- **The ledger's `messages` cell stays**, because the parent still sends the failure ladder's steers itself and the watchdog sends none of its own — record every `SendMessage` there (`dispatch.md`), sent-at time per message, and whether a reply landed.
- **Nothing on the ladder recalls an agent.** `SendMessage` is the strongest autonomous action available to the parent; it reaches the lost-but-active unit and cannot reach a genuinely hung one, which only `TaskStop` touches, and only on the user's word. A recall is recoverable — `harness.md` has why, and what it costs.
- **`done` is what tells the parent, at a `--status` read, whether a unit is still working** — not an alarm, and nothing on the watchdog's own ladder gates on it. It is *not* `stop_reason == "end_turn"`: that field is absent from a real share of transcripts, so testing it alone reads a finished unit as still-running (`harness.md` has the measured coverage). Keep the honest limits: it reads shape, never content, so a complete-but-wrong or complete-but-empty answer reads as done.
- **Degradation, in order.** The step-2 probe returning nothing **on stdout and nothing on stderr**, or the first parse returning null → disable silently, write one ledger line, and never warn again per sample. Empty stdout *with* a line on stderr is not degradation and never disables the sensor (step 2 owns that case). A parse error on a partially written line never fails the run. **Fail open**: an absent signal means no alarm, never a recall. Keep the between-dispatch budget projection running either way, because the watchdog is an enhancement that vanishes when the transcript layout changes.
- **What no signal detects** — `harness.md` lists the blind spots. Compensate rather than trust: Step 5 is the only defence against the confident-wrong agent, and no watchdog line is evidence that a report is true.

## The budget rail

**Reading `--status` at each bring-current point is the whole of how rail 4 gets checked.** Compare each row's `spend` against 4× that row's own estimate, and hold your own projection across everything in flight and already landed against the task ceiling. The ceilings and their floors are the table in `../SKILL.md`, `## Rails`. The same constant at both token scopes is deliberate: a per-task ceiling alone lets one runaway unit eat the whole budget before anything notices, and a per-unit ceiling alone never sees the aggregate. **Neither half has a sensor. Nothing here prints itself — you fire this rail on figures you read.** On a crossing: send the ladder's message so the unit's work is not lost, let it and everything else in flight finish, launch nothing new against that row, and surface.

Three properties travel with it:

- **Projection, not arrival.** Before each dispatch — the final one above all — add the pending unit's estimate plus everything in flight to what has already landed. A projection built from band midpoints is an **upper bound**, not a forecast, so say which kind of figure you are holding when you stop. An actual that lands past the rail with nothing left to dispatch is named as a rail the run outran, never silently absorbed.
- **The estimate must stay honest**, because it sets its own ceiling. The journal's `run` lines record estimate against actual on every run, hits included. A drift toward high estimates shows up there as a widening gap and becomes a retirement candidate against the multiplier itself.
- **Reaching the ceiling is a surfaced event, and so is landing well under it.** Both directions are information.

**Wall clock is a surfaced event, not a stop.** Nobody is waiting in an unattended run, so elapsed time is not itself a harm, and the runaway it once caught is now read continuously off `--status` at each bring-current point, which an aggregate rail never could. Print the overrun; keep running.
