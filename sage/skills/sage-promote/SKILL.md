# Sage promotion

Use only after explicit `$sage-promote` invocation. By default, assess both installed knowledge and the Sage source repository for evidence-backed additions, corrections, and obsolescence. Source improvements may edit Main Sage, promotion instructions, and helpers; leave them uncommitted for human review and later manual installation. Source tasks remain closed and their logs unchanged. Preserve the user’s scope, authority, and explicit model choices.

Use GPT-5.6 or higher for all promotion reasoning work. Apply the shared [model eligibility policy](../sage/references/delegation.md#model-eligibility) before inline work, dispatch, worker reuse, or resume, and pass it to every worker.

1. Read the shared [runtime paths and discovery](../sage/references/runtime.md), resolve and announce the root, and use `list-runs` to locate a bounded source set. Register user-supplied historical paths when needed. Open the separate coordinator run in the same root. Read [promotion](references/promotion.md) for qualification, roles, recovery, and landing, and [source promotion](references/source.md) for checkout discovery and uncommitted source delivery unless the user limited this pass to installed knowledge.
2. Qualify each source as an integrity-valid terminal `completed`, `failed`, or `stopped` run with reconciled effects. Quarantine invalid inputs unchanged. Bound the run set and candidate count before extraction.
3. Extract candidate rules, cues, qualifiers, falsifiers, direct evidence, counterevidence, alternative explanations, and retrieval feedback. Reconcile each with retained knowledge lineage and current source behavior; choose destinations per candidate. An empty store does not rule out correcting or removing obsolete source guidance. A tiny pass with no reusable candidate or source improvement reports `no_change` directly and spawns no ceremonial team.
4. For an actual knowledge action or source patch, obtain three distinct live actors: a candidate author, adversarial refuter, and reviewer. The same three may cover both destinations. The coordinator does not invent their IDs or fill one of those roles. Use an optional Luna-high scout for a worthwhile bounded corpus, Sol-high/xhigh for guided candidate authorship, Astra-high for ambiguous or causal refutation, and a separate Sol-xhigh reviewer. These are uncalibrated priors; capability and user choice win.
5. Give the refuter the proposal, declared class, source evidence, counterevidence, and relevant retained record, without a target verdict. `refutation.outcome: passed` means the proposed action survived that challenge; it never means a refuted earlier rule is true. The reviewer independently dispositions every finding and applies the class-specific evidence predicate. Structural identity separation is not evidence of behavioral independence.
6. Draft the exact knowledge proposal using [knowledge](references/knowledge.md) and/or a source patch using [source promotion](references/source.md). Confounded transfer stays `provisional`; unresolved material contradiction stays `contested`; a fired falsifier may become `refuted`; intentional removal becomes `retired`. Preserve those limits when translating evidence into source behavior. Review votes, repetition, selection frequency, and disuse cannot replace evidence.
7. For installed knowledge, stage a complete generation against the observed current pointer, validate the store, then activate only if the target’s recorded parent and live expected pointer still match. For source, apply the independently reviewed patch against its checked baseline and verify the resulting working tree. The coordinator alone owns both landings. They are separate effects: knowledge rollback changes its pointer; source recovery reverses only this pass’s edits. Leave Git staging, commits, pushes, and real installation to the user.
8. Report each destination’s result separately, with the coordinator run and checkpoint, source runs, quarantines, no-change reasons or actions, assignments and overhead, actors and independence evidence, class gate and counterevidence dispositions, generation hashes, source diff and review-note paths, recovery targets, checks, and unknowns. Source delivery is complete when verified edits are ready for human review; it does not mean committed or installed. Never claim installed behavior, cost, model placement, or semantic proof without direct observation.

The helper validates structure, reference closure, immutable generation integrity, and cooperative expected-pointer checks. It is neither a semantic grader nor a physical lease.
